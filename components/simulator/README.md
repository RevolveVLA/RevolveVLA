# simulator
Gazebo Kura (gz-sim 11 / gz-physics 10 main) + MuJoCo physics for the PartNet kitchen and the mobile
Panda. Ported from the earlier pipeline's gz demo (scripts, worlds) and simulator plugin (replay, live
phase validator, save/restore), with every threshold read from specs/tasks/<t>/task.yaml.

## Build and test
```
./revolve build simulator [--clean]   # image revolve-simulator (deps only), then Kura with colcon inside it
./revolve test simulator              # pytest tests/ (all sim jobs in containers, run concurrently)
```
- `Dockerfile`: dependencies only (gz-kura-mujoco's apt list + rosbags, pillow, pydantic, FastAPI, uvicorn).
  No ROS (replay and bags need none). `ros/Dockerfile`: revolve-simulator-ros, the thin deps-only ROS 2 Jazzy
  layer FROM this image for `rollout` (built by `./revolve build evaluation`).
- `build.sh`: `ThirdParty/gz_kura/fetch.sh` (kura.repos pins + ThirdParty/patches) and colcon into
  `ThirdParty/gz_kura/install` (git-ignored; build/, log/, .ccache/ too), mounted at `/opt/gz_ws` as
  the earlier gz build did. Rebuilds are incremental. franka_description is read in place from the
  ThirdParty submodule (nothing to build).
- Assets (PartNet-Mobility, ReplicaCAD: non-commercial) are read in place from `assets/` (git-ignored, repo root)
  through the repo mount; never copied into git or the image. They are made by `assets_pipeline/` (moved from
  the earlier gz demo, see below).

## Asset pipeline (`assets_pipeline/`)
Downloads (licence-bound, never commit them): PartNet-Mobility 11211 + 46452 (SAPIEN download, non-commercial) into
`assets/partnet_mobility/dataset/<id>/`; the ReplicaCAD table and cup (8 files, 1.2 MB; CC BY-NC 4.0, credit Meta
Habitat 2.0 if the table appears in a video) into `assets/replicacad/`:
```bash
HF=https://huggingface.co/datasets/ai-habitat/ReplicaCAD_dataset/resolve/main
for f in LICENSE.txt README.md \
  objects/{frl_apartment_table_01.glb,frl_apartment_cup_01.glb} \
  objects/convex/{frl_apartment_table_01_cv_decomp.glb,frl_apartment_cup_01_cv_decomp.glb} \
  configs/objects/{frl_apartment_table_01,frl_apartment_cup_01}.object_config.json; do
  curl -fsSL --create-dirs -o "assets/replicacad/$f" "$HF/$f"
done
```
- `make_partnet.sh [--no-test|--snapshot]`: fridge + cabinet -> `assets/generated_partnet/` (URDF -> SDF + CoACD via
  `urdf_to_gz.py`, configs in `configs/`), then `load_test.py` loads each alone under the MuJoCo plugin.
- `make_replicacad.sh [--no-test|--snapshot]`: table_01 + cup -> `assets/generated/`.
- `make_room.py [--offline]` (host, stdlib): the room shell `assets/generated/kitchen_room_*`, CC0 textures cached
  in `assets/textures/`.
The two shell scripts re-run themselves in revolve-simulator (coacd + trimesh in its last layer) with
`ThirdParty/gz_kura/install` mounted, so `./revolve build simulator` comes first. They pass `--gpus all` as the
legacy scripts did. Only paths changed in the move; the "Generated by asset_pipeline/..." headers written into the
models are kept as they were, so regenerated files match the existing ones.

## Entrypoints (`src/sim/cli.py`, run under `revolve_common.wrapper`)
| Command | What | Was |
|---|---|---|
| `scene-check` | kitchen without robot: door/drawer limits, rest drift/jitter, cup on its shelf | `kitchen_test` |
| `robot-smoke` | mobile Panda spawn + smoke test in the kitchen | `kitchen_robot_test` |
| `can-demo` | Panda can-on-plate | `headless` can demo |
| `episode --name fridge\|drawer` | scripted episode, fed through the live phase validator: its own checks + per-phase verdicts + phase states | `episode <name>` |
| `replay --plan RUN --attempt A` | AutoMoMa plan attempt: offline verdict + per-phase verdicts + `phase_states/` + `state_log.npz` + MCAP `bag/` | `replay` + `live_validate` + bag write |
| `restore-check --source D --phase P` | restore `D/phase_states/P_start.npz`, run on, compare with the source | `live_validate --restore` |
| `rollout --start D0 --out D [--restore D1:PHASE]` | closed-loop policy rollout (image revolve-simulator-ros): `closed_loop_system` (rebased on the live phase validator, policy mode: `phases.PolicyBoundaries`) follows the actions `ros_relay.py` brings from ROS 2; per-phase verdicts + phase states; a phase still running at the end fails (`phase_ended`) | `gz_closed_loop.sh` + `policy_episode.py` + `live_validate` |
Exit code = verdict. `--video` renders the scene camera to `<out>/video.mp4` (GPU). The rollout's host side
(serve, Rosetta's runner, networks) is components/evaluation.

Host side: `launch.py` (docker SDK) starts a job container with the repo read-only at /repo, runs/
read-write, the Kura install read-only, the wrapper as the command (GET /status, /result, POST /cancel
on the container's IP; no published ports), and writes job.json; the wrapper writes status.json,
result.json and stdout.log into the job dir.

## Outputs of a phase run (`episode`, `replay`, `restore-check`)
`phase_report.json` (per phase: status, checks named by metric with value/threshold/t_fail, start state;
`conditions` = the task.yaml gates used; `metric_states` = the states they were judged on; `result`
= first failed phase), `phase_states/<phase>_start.npz` (+ `_start_next.npz`), `state_log.npz`,
`summary.json` (the ported gz checks), `verdict.json` (replay: the offline verdict), `bag/`, `bag.json`,
`bag_check.json` (replay), `restore_check.json` (restore).

## Layout
`src/sim/`: the gz Python systems and helpers (flat: gz loads systems by module name from
GZ_SIM_SYSTEM_PLUGIN_PATH); `spec.py` is the bridge to specs/ (replaces the earlier pipeline's plugin loader and the
task validator.py files). `src/worlds/`: the world files. `src/egl/`: the NVIDIA EGL vendor file for GPU
rendering. Generated robot models go to `runs/models/` (with the training cameras) and `runs/models/plain/`.
